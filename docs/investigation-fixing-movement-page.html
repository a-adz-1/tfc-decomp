Metamod or AMX Mod X?

Metamod plugins (like TFC Fixes) are compiled code: faster, and the only kind that can change the movement code itself. AMX Mod X plugins are scripts: easier to install and edit, but slower and more limited. All the movement fixes are best together in one metamod plugin. More on the plugin types →

  • Instant unstick: AMX Mod X can do it. A plugin checks each player before their move, and if their box is inside something, searches nearby spots and moves them to a free one, so the game never freezes them.
  • Ramp bug: only a workaround in AMX Mod X. The cause is inside the game's movement code, which AMXX can't change. A plugin could spot the symptom afterwards (a fast slide suddenly at zero speed with nothing blocking) and give the speed back, but the player still loses that moment. The real fix needs a metamod plugin.
  • Corners: no. Same place in the movement code, and from outside you can't tell a real corner stop from a harsh one.
  • Either way, players' PCs still predict the original movement, so you'd see one small correction when a fix kicks in.

2Getting stuck on walls

Frozen, then snapped back

A blast, a lift, a door or a teleporter can leave your box slightly inside a wall. The server then skips your movement entirely. It tries one tiny shove every 0.05 s, and the first 27 of those are too small to be used, so it can take over a second. Your own game searches every nearby free spot at once, so on your screen you walk free, then the server pulls you back.

Fix: when you're stuck, the server searches all the nearby free spots straight away too, the same way your game does. Both then agree, so no freeze and no snap-back.

Best as metamod (AMX Mod X can too)

Stopping dead in corners

When one move hits three surfaces at once (two walls, or a wall and a slope), the movement code gives up and sets your speed to zero. That's intended, but harsh.

Fix (optional): instead of stopping, keep the part of your speed that slides along the best of those surfaces. It changes how corners feel, so it would be off by default and only switched on if players vote for it.

Metamod only

Catching on certain map edges

Some snags are in the map itself: how its collision shapes were compiled. That's fixed per map, by recompiling it or adding invisible clip brushes over the bad edge.

Not a plugin job

3The ramp bug (dead stops)

The slide code keeps a list of the surfaces it bumps into during a move, but never checks for repeats. With tiny moves (high fps) it can bump the same slope twice. Two identical surfaces then count as a "corner", and the direction along that corner is zero, so your speed becomes zero: the dead stop.

Fix: ignore a surface that's already in the list. A plain slope is then never mistaken for a corner. Nothing else about movement changes.

Metamod (AMX Mod X: workaround only)

4Ramp slides changing with fps

Whether you touch the floor for one frame before a ramp decides how much speed you keep (all of it, or only part when you hit the slope in the air), and where your frames fall depends on your fps. That's how the movement responds to frame timing, not a bug.

Changing it would alter every ramp slide, and because your own game predicts your movement with the original rules, a server-only change would correct you on every ramp. It would need a change on players' PCs too, and the community's agreement. For now, fps_max 100 gives the classic behaviour.

Neither plugin type alone

5Getting stuck on players

The server checks your movement against where other players were on your screen (lag compensation), so two players can end up overlapping. The freeze that follows is the same as with walls, so instant unstick fixes it. The overlap itself happens inside the engine and would need an engine change (possibly with ReHLDS later). Until then: hold jump, duck or fire when stuck in a player, and the server searches for a free spot at once.

6How the fixes would work

  • One server plugin (metamod), next to the TFC Fixes plugin the OTFC servers already run, with each fix switchable on its own.
  • It runs the game's movement step using the version Valve published in its Half-Life SDK for mod makers, with the fixes added.
  • Your PC still predicts your movement the original way. So at the moments a fix kicks in (where you'd have frozen or stopped dead), you'd see one small correction instead. Everywhere else, nothing changes.

7How we'd prove them

  1. On our test rig, which runs the real game and engine: the ramp-slide runs that stopped dead at 1000 fps should carry on, and every other result should stay exactly the same.
  2. Stuck tests on the rig: a player pushed into a wall or another player should be freed within one move.
  3. A test night on the EU pickup server with the fixes on, then a vote on the corner option.
